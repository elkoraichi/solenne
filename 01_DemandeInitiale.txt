# Projet : Maison de campagne de Solenne — plateforme privée pour amis, événements et séjours

## 1. Contexte

Solenne est mon amie et elle entretient une relation très proche avec ma fille Houyam.

Elle vient de faire l'acquisition d'une grande maison de campagne d'environ **200 m²**, comprenant plusieurs chambres ainsi que **deux bureaux**.

La maison a plusieurs usages :

* Solenne y séjourne personnellement.
* Elle souhaite pouvoir y recevoir ses amis.
* Elle souhaite y organiser ponctuellement des événements : weekends entre amis, repas, fêtes, activités, journées à thème, etc.
* Elle souhaite pouvoir y télétravailler.
* Elle souhaite également mettre ponctuellement la maison à disposition de ses amis et connaissances pour des séjours privés :

  * quelques heures ;
  * une journée ;
  * un weekend ;
  * plusieurs jours ;
  * une semaine ou davantage.

L'objectif est de créer une **application web privée, élégante, simple et conviviale**, permettant de gérer la vie de cette maison et les relations avec les amis de Solenne.

Ce n'est pas un site de location commerciale type Airbnb.

Il s'agit avant tout d'une **maison privée partagée avec un cercle d'amis et de connaissances**.

---

# 2. Objectifs principaux

L'application doit répondre à deux besoins principaux.

## A. Organiser les événements

Solenne doit pouvoir créer et gérer des événements organisés dans la maison.

Par exemple :

> Weekend barbecue chez Solenne
> Samedi 12 septembre → dimanche 13 septembre
> 10 personnes maximum
> Barbecue, piscine, randonnée, jeux de société

Les amis invités doivent pouvoir :

* consulter les événements ;
* indiquer s'ils participent ou non ;
* éventuellement indiquer combien de personnes les accompagnent ;
* préciser leurs disponibilités ;
* voir qui participe ;
* voir les informations pratiques ;
* voir les activités prévues ;
* proposer ou sélectionner ce qu'ils peuvent apporter ;
* échanger des informations liées à l'événement.

L'objectif est de remplacer les conversations WhatsApp interminables par un espace organisé.

---

# 3. Gestion des séjours / demandes de réservation

Le deuxième objectif est de permettre aux amis de Solenne de demander à utiliser la maison.

Exemple :

> "J'aimerais venir avec ma famille du vendredi 18 au dimanche 20 septembre."

L'utilisateur doit pouvoir effectuer une demande directement depuis le site.

Il doit pouvoir :

* choisir une date d'arrivée ;
* choisir une date de départ ;
* indiquer le nombre de personnes ;
* préciser les personnes qui viennent avec lui ;
* préciser éventuellement le motif ou le type de séjour ;
* ajouter un commentaire ;
* éventuellement indiquer ses besoins particuliers.

La demande ne doit **pas être automatiquement acceptée**.

Elle doit passer par une validation de Solenne.

Workflow :

**Demande → En attente → Acceptée / Refusée / Annulée**

Une fois acceptée :

{Modification Yassine} * les dates peuvent rester disponibles ou deviennent indisponibles selon la situation; 
par exemple, une personne qui réserve la maison en premer et elle est seule, la maison peut rester disponible pour acceuillir une autre personne ou un couple.
* les autres utilisateurs voient que la maison est occupée, sans nécessairement connaître les détails privés ; Ils peuvent réserver si la maison est indiquée comme étant disponible.
* Solenne et le demandeur reçoivent une notification.

---

# 4. Principe essentiel : maison privée

L'application doit être pensée comme un **club privé / maison d'amis**, et non comme une plateforme commerciale.

Il n'y a donc initialement :

* aucun paiement ;
* aucune commission ;
* aucune facturation ;
* aucune publication publique ;
* aucun référencement public des disponibilités ;
* aucun moteur de recherche public.

Toutes les informations sont privées.

# 6. Authentification

L'application doit être privée.

Un utilisateur ne doit pas pouvoir créer librement un compte.

Le principe souhaité est :

1. Solenne invite une personne.
2. La personne reçoit un lien d'invitation.
3. Elle crée son compte.
4. Elle complète son profil.
5. Elle peut ensuite accéder à l'application.

Prévoir une authentification moderne et sécurisée.

Si le projet possède déjà un système d'authentification, réutilise-le plutôt que d'en créer un nouveau.

Prévoir idéalement :

* email ;
* mot de passe ;
* récupération de mot de passe ;
* session sécurisée ;
* gestion des rôles ;
* possibilité d'ajouter ultérieurement Google/Apple ou magic link.

# 26. Sécurité et confidentialité

La confidentialité est essentielle.

L'application contient des informations personnelles et des informations sur les déplacements des personnes.

Il faut donc :

* sécuriser l'authentification ;
* contrôler les permissions côté serveur ;
* ne jamais faire confiance uniquement au frontend ;
* protéger les données personnelles ;
* empêcher un utilisateur de consulter les données auxquelles il n'a pas accès ;
* journaliser les actions importantes de l'administrateur ;
* protéger les invitations ;
* sécuriser les tokens ;
* prévoir les bonnes pratiques RGPD.

# 30. Cas limites à gérer

Ne pas oublier notamment :

* deux personnes demandent les mêmes dates ;
* Solenne accepte une demande alors qu'une autre vient d'être acceptée ;
* un utilisateur annule son séjour ;
* Solenne annule un séjour ;
* un événement est déplacé ;
* un événement est annulé ;
* un invité change sa réponse ;
* un événement dépasse sa capacité maximale ;
* une personne invite un accompagnant ;
* une personne n'est plus autorisée à utiliser la maison ;
* une date est bloquée après une demande ;
* une demande couvre une période déjà occupée.

Tous ces cas doivent être gérés proprement.
